# نسخهٔ ۳٫۶ — تکمیل اتصال‌ در فروش VPN روی Cloudflare

## دامنهٔ تغییر

این تغییر **بخش موجود «فروش VPN» را تکمیل می‌کند**؛ یک پنل PHP موازی، iframe یا نصب‌کنندهٔ لینوکسی به Worker اضافه نشده است. امکانات قبلی کیف پول، خرید/تمدید، انبار، نمایندگی، کد هدیه، مینی‌اپ، پرداخت، گزارش و چندربات حفظ شده‌اند. به مهاجرت جدید SQLite نیاز نیست.


## پنل‌ها

با دو اتصال جدید، رجیستری اکنون ۱۷ حالت اتصال/انبار دارد: Remnawave، Rebecca، Marzban، Marzban 1.x، Marzneshin، PasarGuard، x-ui/3x-ui، x-ui Token، Alireza single، Alireza inbound، S-UI، Hiddify، WGDashboard، Guard، MikroTik، IBSng و انبار دستی.

### Remnawave

1. در «کارگاه ربات ← فروش سرویس ← پنل‌ها»، نوع **Remnawave** را انتخاب کنید.
2. نشانی HTTPS واقعی پنل و توکن API با دسترسی لازم را وارد کنید. از نشانی صفحهٔ dashboard استفاده نکنید.
3. ابتدا می‌توانید پنل را با فیلد Squad خالی ذخیره و منابع را دریافت کنید؛ سپس Squadهای معتبر را وارد کنید. دکمهٔ **منابع**، `/api/internal-squads` را می‌خواند. UUIDها را با کاما در فیلد Squad وارد کنید. هر پلن باید حداقل یک Squad داشته باشد.
4. سقف دستگاه HWID را تعیین کنید؛ صفر یعنی بدون محدودیت. اگر Cloudflare Access فعال است، Service Token آن را نیز در فیلدهای جداگانه وارد کنید.
5. «آزمایش» از `/api/system/stats` استعلام می‌گیرد. «نودها» وضعیت اتصال را نشان می‌دهد؛ اتصال مجدد با UUID و `/actions/restart` انجام می‌شود.
6. پلن با روز بزرگ‌تر از صفر بسازید. گزینهٔ شروع از اولین اتصال و زمان نامحدود برای این قرارداد **پشتیبانی نمی‌شود و رد می‌شود**؛ تاریخ ساختگی بلندمدت به‌جای نامحدود ارسال نمی‌شود.

عملیات: ایجاد و خواندن، تمدید، حجم/روز اضافه، فعال/غیرفعال، حذف، ریست مصرف و تعویض اشتراک. ساخت با `NO_RESET` انجام می‌شود؛ تمدید مصرف را به‌طور ضمنی ریست نمی‌کند. تغییر حجم و زمان مقدار مطلق دارد تا تکرار درخواست مقدار را دوباره اضافه نکند.

API فعلی با `username` برای PATCH و شناسهٔ دریافتی برای actionها استفاده می‌شود. این به معنی پشتیبانی خودکار نسخه‌های قدیمی با قرارداد متفاوت PATCH نیست.

نمونهٔ تنظیم اختصاصی پلن:

```json
{
  "squadIds": ["1fc895a1-282a-4277-875d-bb850263df2e"],
  "hwidDeviceLimit": 3
}
```

UUID نمونه را با Squad واقعی خود جایگزین کنید.

### Rebecca

1. نوع **Rebecca**، نشانی HTTPS و توکن API را وارد کنید.
2. «منابع» سرویس‌ها را از `/api/v2/services` می‌خواند. شناسهٔ عددی واقعی را در **Rebecca Service ID** ثبت کنید.
3. سقف IP را تنظیم کنید. پلن‌ها می‌توانند `serviceId` و `ipLimit` اختصاصی در JSON داشته باشند.
4. «آزمایش» از `/api/system` استفاده می‌کند.

ساخت/ویرایش با `/api/v2/users` و خواندن/حذف/ریست/تعویض اشتراک با `/api/user/{username}` انجام می‌شود. شروع از اولین اتصال با `on_hold_expire_duration` پشتیبانی می‌شود. اتصال مجدد نود برای Rebecca تبلیغ نشده است، چون قرارداد آن در مرجع بررسی‌شده تأیید نشده بود.

```json
{ "serviceId": 2, "ipLimit": 2 }
```

تحویل این adapter مبتنی بر `links` و `subscription_url` است. صفحات اختصاصی Access Insights، خروجی‌های ویژهٔ پروتکل‌های اضافی Rebecca و ابزارهای مدیریتی خارج از چرخهٔ فروش، انتقال کامل داده نشده‌اند.

### ایمنی ساخت

- توکن‌ها با Vault رمزگذاری می‌شوند و پاسخ API مدیر آن‌ها را برنمی‌گرداند.
- پاسخ HTML صفحهٔ ورود یا JSON نامعتبر به معنی «کاربر وجود ندارد» نیست؛ فقط HTTP 404 نبود کاربر را نشان می‌دهد.
- قطع پاسخ پس از ایجاد کاربر، عملیات را به `review` می‌برد و مبلغ در حالت رزرو می‌ماند.
- تطبیق مجدد علاوه بر نام و حجم، marker دقیق `BotPanel <operationId>` را بررسی می‌کند؛ حساب هم‌نام متعلق به سیستم دیگری تصاحب نمی‌شود.
- تغییر نشانی یا نوع پنل، کش اطلاعات ورود قبلی را باطل می‌کند.

## درگاه‌های جدید

در «روش‌های پرداخت»، چهار روش زیر علاوه بر ۱۰ روش قبلی قابل انتخاب‌اند:

| درگاه | ساخت فاکتور | تأیید امن | نکته |
|---|---|---|---|
| TonPay | `tonpays.online`، API key، مبلغ تومان | استعلام invoice، تطبیق order، وضعیت completed/paid و مبلغ نهایی | callback صرفاً شروع استعلام است |
| BluPal | `blupal.net`، API key، مبلغ ریال | استعلام invoice، PAID و تطبیق مبلغ ریالی | از polling استفاده می‌شود؛ تنظیم callback عمومی فروشنده در Worker لازم نیست |
| QubePay | `cubevps.ir`، Bearer token، `price_amount` تومان | استعلام order با توکن، شناسه/وضعیت/مبلغ | مسیر انتخاب کارت/رمزارز در صفحهٔ خود درگاه؛ callback رمزنگاری‌نشده اعتبار ایجاد نمی‌کند |
| Tronado | `bot.tronado.cloud`، API key و آدرس عمومی TRON | HMAC-SHA512 روی بدنهٔ خام با `X-Tronado-Sig` | کلید IPN مستقل اجباری است؛ verify سمت مشتری جایگزین وب‌هوک نیست |

### تنظیمات و مبلغ

- کلیدها را فقط در فرم رمزدار پنل یا Secretهای Cloudflare وارد کنید؛ در Git یا گفتگو قرار ندهید.
- Tronado به **API key + IPN Signing Secret + آدرس کیف پول عمومی** نیاز دارد. درصد سهم کارمزد کسب‌وکار قابل تنظیم است. کلید خصوصی/عبارت بازیابی لازم نیست.
- نرخ TRX در Tronado از خود درگاه گرفته و مبلغ شش‌رقمی در فاکتور ذخیره می‌شود. تغییر نرخ بعدی، فاکتور قبلی را عوض نمی‌کند. گردکردن رو به بالا از کم‌پرداختی ناشی از اعشار جلوگیری می‌کند.
- QubePay می‌تواند کارمزد درصدی صحیح و مبلغ ثابت تومان به فاکتور اضافه کند. موجودی مشتری فقط به‌اندازهٔ مبلغ درخواستی شارژ می‌شود، نه کارمزد.
- درگاه‌های polling در Cron فعلی و به‌صورت محدود و نوبتی بررسی می‌شوند. مشتری نیز می‌تواند «بررسی پرداخت» را بزند.
- کم‌پرداختی، عدم تطابق مبلغ/شناسه یا پرداخت دیرهنگام Tronado به شارژ خودکار کامل تبدیل نمی‌شود. پشتیبانی باید وضعیت واقعی را بررسی کند؛ در صورت کسر کارمزد از مبلغ نهایی TonPay/BluPal، مبلغ کمتر از اعتبار درخواستی خودکار تأیید نخواهد شد.
- تکرار callback، تکرار verify و تکرار Cron نباید کیف پول را دوباره شارژ کند؛ ثبت پرداخت از دفترکل و شناسهٔ یکتا استفاده می‌کند.
- مسیر Tronado فقط POST امضاشده به `/service-pay/notify/<id>?key=<nonce>` را می‌پذیرد. هیچ فیلد JSON از API مشتری نمی‌تواند جای اعتبارسنجی امضا را بگیرد.

قابلیت‌های ریز تنظیم کارمزد/بانک/احراز هویت در همهٔ نسخه‌های این درگاه‌ها، یا درگاه‌های فرعی دیگر موجود در سورس PHP مانند AtlasPay/Aban/Variza، در این نسخه ادعای پوشش کامل ندارند.

## استقرار Cloudflare

```bash
npm ci
npm run build
npm test
npm run smoke
npx wrangler deploy --dry-run
# فقط برای نصب جدید یا اگر از قبل تنظیم نشده است:
npx wrangler secret put VAULT_KEY
npm run deploy
```

**اگر VAULT_KEY از قبل دارید آن را تعویض نکنید**؛ بدون مهاجرت، اطلاعات رمزگذاری‌شدهٔ موجود خوانده نمی‌شود. مقدار باید حداقل ۳۲ کاراکتر تصادفی باشد. bindingهای `BOT_STATE` و `BOT_KV` و Cron دقیقه‌ای فعلی را حفظ کنید. تمام APIهای بیرونی باید HTTPS با گواهی معتبر و از شبکهٔ Cloudflare قابل دسترسی باشند.

پس از استقرار:

1. نسخهٔ ۳٫۶ را در پنل بررسی کنید؛ URL عمومی Worker را در تنظیمات خدمات درست وارد کنید.
2. توکن ربات، وب‌هوک تلگرام و کلید Vault را بررسی کنید.
3. برای هر پنل، «آزمایش» و «منابع» را اجرا کنید و شناسه‌ها را از همان سرور بردارید.
4. با یک پلن کم‌هزینه چرخهٔ خرید، تحویل، اتصال واقعی کلاینت، مصرف، تمدید، ریست و حذف را تست کنید.
5. برای هر درگاه یک تراکنش واقعی کم‌مبلغ، دوبار بررسی همان فاکتور، و ثبت دقیق یک‌بارهٔ دفترکل را بررسی کنید.
6. قبل از فعال‌کردن فروش عمومی، Cron، خطاهای Worker، backup و بازیابی را بررسی کنید.

استقرار واقعی در حساب Cloudflare کاربر و تراکنش واقعی با پنل‌ها/درگاه‌ها در این تغییر انجام نشده‌اند.

## شواهد آزمون

- `npm test`: **۲۶۸ تست موفق**؛ شامل ۱۷ تست افزوده برای APIهای جدید، تایم‌اوت، تطبیق مالکیت، مبلغ، امضا، تکرار پرداخت و فیلتر فرم‌ها.
- `npm run smoke`: **۶۷ بررسی موفق**.
- `npm run build` و `wrangler deploy --dry-run`: موفق؛ bundle قابل ساخت برای Worker.
- `npm run test:workerd-services`: موفق روی Workerd محلی با Durable Objects/SQLite واقعی؛ ورود، ثبت رمزگذاری‌شدهٔ اتصال‌ها و درگاه‌ها، پلن‌ها، متادیتا و فایل‌های مینی‌اپ. این تست عمداً فقط localhost را می‌پذیرد و داده‌های آزمایشی غیرفعال ایجاد می‌کند.
- اجرای کامل Playwright در این محیط انجام نشد؛ دانلود Chromium از CDN با خطای اتصال TLS قطع شد. تست DOM فرم‌ها اجرا شده، اما جای تست مرورگر واقعی یا اتصال تولیدی را نمی‌گیرد.

برای تکرار آزمون محلی در دو ترمینال:

```bash
npx wrangler dev --local --ip 0.0.0.0 --port 8787 \
  --var VAULT_KEY:local-only-testing-key-at-least-32-characters
npm run test:workerd-services
```

تست از رمز آزمایشی محلی استفاده می‌کند؛ آن را روی محیط واقعی اجرا نکنید. هیچ سرور VPN یا درگاه واقعی برای پاس‌شدن این تست‌ها لازم نیست، بنابراین نتیجهٔ سبز آن‌ها تضمین اتصال خارجی نیست.
